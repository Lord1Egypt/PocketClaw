## Source of truth for generated branding

    core/src/web/frontend/scripts/generate-brand-assets.py    APERTURE geometry (canonical, read-only)
      └─ tool/generate_android_launcher_icons.py              PocketClaw-owned repo-level generator
           ├─ android/.../drawable-*/ic_launcher_foreground.png
           ├─ android/.../drawable-*/ic_launcher_monochrome.png
           ├─ android/.../mipmap-*/ic_launcher.png
           ├─ android/.../drawable-nodpi/pocketclaw_mark.png
           ├─ android/.../drawable/ic_stat_pocketclaw.xml
           ├─ assets/branding/android-launcher/ic_launcher_master.png
           └─ assets/branding/pocketclaw-icon.png              README

One geometry, one generator. The generator imports the Core brand module by path
and never writes to it. `--check` regenerates everything in memory and compares
bytes, which is what `test/unit/brand_asset_contract_test.dart` runs, so a
hand-edited or stale asset fails a test rather than shipping.

Every PocketClaw identity image in the tree is an output of this chain. The
glossy 3D mark (`assets/branding/pocketclaw-mark.png`, with its splash copy
`drawable/pocketclaw_mark.png`) and the desktop tray/Windows icons
(`assets/app_icon.png`, `assets/icon.ico`) were removed in PC-DEF-081/083: the
first was a design direction the launcher no longer uses, and the others served
a desktop build PocketClaw does not have. No branding image is a Flutter asset;
none is packaged into the APK except the Android resources above.
